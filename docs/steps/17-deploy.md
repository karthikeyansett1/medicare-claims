# Step 17 — publish a truthful, no-cost demo

## What and why

Published [Atlas on Hugging Face](https://huggingface.co/spaces/karthikeyansett1/medicare-provider-performance), with the [canonical live app](https://karthikeyansett1-medicare-provider-performance.static.hf.space). Four browser-interactive dashboard views retain full Samples 1 and 2; four clickable Assistant questions display fixed aggregate SQL results verified against a separate 1,000-member fixture. The public site makes no model calls. Separately authorized, funded owner-run smoke and evaluation evidence lives in `eval/results`; those local runs do not activate live AI on the public site. Resume/interview claims distinguish measured fixed-set regression results from independent human review and generalization claims.

The guide assumed a free Streamlit Space and a small full gold schema. Current evidence required two changes: HF rejected Docker creation with HTTP 402 because this non-PRO account cannot create compute Spaces; seven approved full-data tables measured 922,353,664 bytes. A free static SDK deployment and a 17,588,224-byte fixture database preserve a useful public result with no hosting subscription or per-visit model spend. Optional Docker/Streamlit packaging is retained for a future compute-enabled account, not claimed as deployed. See [current hosting evidence and activation limits](../../deployment/README.md).

## Explain it in an interview

“I separated delivery scope from data scope. The dashboard uses audited provider aggregates from the full two-sample warehouse. The public SQL demo uses a tiny, independently verified fixture and says so on screen. When current hosting policy contradicted the guide, I published a browser-only experience without exposing database credentials or implying that saved results were AI responses. A future public live assistant still needs a separately authorized server deployment, reviewed evaluation evidence, and durable server-side spending controls.”

Funded owner-run validation is separate from deployment. The eight public few-shot smoke cases produced seven passes and one mismatch, with $0.471646 recorded usage cost; these are examples already available to the model, not a held-out accuracy score. The local evidence under `eval/results` records the funded evaluation runs and their completion status. Deployment completion alone establishes neither held-out accuracy, v1/v2 improvements, repeated-run variance nor faithfulness. Stacked GitHub draft PRs remain unmerged; the implementation branch is the repository entry point until separately authorized integration.
